# 11 — Demo UI (control room)

**Role:** one browser page for presenting and rehearsing the demo. It shows the conversation, the carrier's state, the live alerts and audit rows, and the binding QR code side by side. It only drives what `make demo` and the showcase scripts already drive. Two tabs (T1): **Control room** (the Stage and panes 1–4) and **Ops**, which runs a fixed allowlist of `make` targets: the *local* group, and, behind a gate and typed confirmations, the *aws* group: the runbook's AWS steps, run on the laptop with the credentials already in the root `.env` (§2, "The Ops tab").
**Runs on:** the presenter's laptop only: a container in compose on `127.0.0.1:8090` (scripted agent), or `uv run` on the host on `127.0.0.1:8091` (`make showcase-ui`, Bedrock when credentials resolve; `make ops-ui` with the Ops tab's aws group on). Demo tooling, not a system component. It is never deployed to AWS.
**Owns:** nothing. No table, no consent, no policy, no carrier credentials. Its code never reads an AWS key: the aws group's `make` children load the root `.env` themselves, as in a terminal (T3). It reads, it calls admin endpoints that already exist, and it starts the allowlisted `make` targets as the user who started it.
**Status:** built 2026-10-09 (step 2): `services/demo-ui`, its compose entry, the kind-only Helm chart `deploy/helm/demo-ui` and `make showcase-ui` (10 §5). ## 2. Shape

FastAPI + HTMX, one static page with no build step, mobile-friendly (the four panes stack on a phone). HTMX 2 and its SSE extension are vendored under `static/` (no CDN at demo time). One server process holds one feed poller and one demo runner. The browser gets HTML fragments and one Server-Sent Events stream, `GET /events`.

  src/demo_ui/views.py      # Jinja2 fragments (autoescaped) for each pane

  src/demo_ui/aws_reset.py  # Reset on ENV=aws (U3): mock load → Alerts /internal/reset → binding re-grant, over HTTP

### The Ops tab (prompt 22, amended by prompt 23; specified 2026-10-11)

**Tabs (T1).** The top bar gets two tabs, `Control room · Ops`. Control room is the Stage and panes 1–4, unchanged (pane 5's `<details>` leaves it). Ops is a second `<section id="tab-ops" hidden>` of the same static `index.html`, shown by `static/ops.js` from the URL hash: `/#ops` opens it directly, any other hash (or none) shows Control room. There is no new page route and no second SSE stream: both tabs live on `GET /` and `GET /events`. The Ops tab works with the stack down (it is how you bring it up). Its fragments load when the tab is first shown (`ops.js` dispatches `ops:open`; the fragments trigger on `ops:open from:body`), so presenting on Control room starts no probe and no AWS call.

**Layout.** Header (full width, `GET /fragment/ops-header`; with the gate off it shows only `AWS runs: off: <reason>` and the banner, since no probe runs): `profile <name> | key pair from .env | default chain` · `region` · `account 1234-5678-9012` (dashed, as the console shows it: a bare 12-digit run is a phone-number hit for `redact.mask`) · the gate (`AWS runs: on`, or `off: <reason>` verbatim) · the cost banner. Below it two columns: left "Run here" (local group) above the one log viewer that both groups share (badge, chips, Stop); right "AWS pipeline", the stepper, with the admin path as a box after step 5. At the bottom, full width, a red-bordered **Teardown** section (`GET /fragment/ops-teardown`), never in the stepper's flow.

**Run here (local runner, O1, O6).** Enabled only when all hold: `ENV=local`; the process is the host run (`DEMO_UI_PUBLISHED_LOOPBACK` is not `1`: the compose and kind containers have no `make`, no Docker and no checkout); `make` is on `PATH`; the checkout root (the directory holding `Makefile` and `mk/`, found from the package location or `DEMO_UI_CHECKOUT`) exists. Otherwise the column is greyed with the reason verbatim: "ENV=aws: the local runner is off; the AWS pipeline is on the right" (U3; amended wording, prompt 23: the right column is no longer copy-only), "runs only in `make showcase-ui` on the host", "make not found", "checkout not found".

The allowlist is data in `ops/allowlist.py`, `TARGETS: tuple[OpsTarget, ...]` with `OpsTarget(name, argv, runner, group, label, needs_stack, env, env_mode, confirm, confirm_when, after, takes_cidr)`, frozen. No env var, flag, file or request can add, change or parameterise a target; changing it means editing `allowlist.py` **and** this table in the same change (`test_ops_allowlist.py` parses the table between the markers and compares). Every argv is a tuple (`shell=False`), starts with `make`, names one target, and fixes `ENV`: `ENV=local` on the local runner, `ENV=aws` on the aws runner. The root `.env` may set `ENV` (`mk/vars.mk` reads it with `:=`, which beats `?=`), and only a command-line `ENV=` overrides it — without `ENV=local`, `make down` would be `terraform destroy`. The only other fixed assignment is `SEED_ARGS=--bind-asish` on `aws-seed-bind-asish`. Two parts are added at run time and nowhere else: `FORCE=1`, appended only after the step's confirm word was typed correctly (targets whose recipe asks: `aws-down`, `aws-down-all`, `aws-admin-close`), and `ADMIN_CIDR=<a.b.c.d/32>` on `aws-admin-open` (the `<cidr>` in its row), validated before it is appended (below).

Columns: `runner` is the group of T2 (`local` | `aws`); `group` is the button section; `env mode` is `scrubbed` (local) or `dotenv` (aws), see "The child's environment"; `confirm` is the word to type (T5), `—` for none, or `deploy if the plan destroys` (only when the last plan's destroy count is not 0, or cannot be read); `after` names the targets whose step must be `done` before Run enables (the order precondition; `—` = none).

The local runner additionally never names a target of the aws runner (`ecr-up`, `push`, `plan`, `deploy`, `outputs`, `cognito-users`, `seed-aws`, `web-chat-sync`, `web-chat-url`, `latency-aws`, `down-all`, `admin-open`, `admin-close`) and never carries `ENV=aws` (O1 holds for it). The local `down`, `demo`, `test-e2e`, `test-report` and the aws `aws-down`, `aws-demo`, `aws-test-e2e`, `aws-test-report` are different entries: the name is the id the route takes, the argv's `ENV` is what makes them different.

**The child's environment** is built from an allow-list, not by deleting from the parent: the keys of the named sets that are present in the UI's environment, plus `NO_COLOR=1`, `PYTHONUNBUFFERED=1`, `TERM=dumb`. Sets: **base** `PATH HOME USER LOGNAME LANG LC_ALL TZ TMPDIR SSL_CERT_FILE SSL_CERT_DIR REQUESTS_CA_BUNDLE HTTP_PROXY HTTPS_PROXY NO_PROXY http_proxy https_proxy no_proxy`; **docker** `DOCKER_HOST DOCKER_CONTEXT DOCKER_CONFIG DOCKER_CERT_PATH DOCKER_TLS_VERIFY DOCKER_BUILDKIT BUILDX_CONFIG`; **uv** `UV_CACHE_DIR UV_PYTHON UV_NATIVE_TLS UV_LINK_MODE`. A key matching `AWS_*`, `TF_VAR_*`, `COGNITO_*`, `*_TOKEN`, `*_BEARER`, `*_SECRET`, `*_PASSWORD`, `*_KEY`, `VIRTUAL_ENV` or `ENV` can never pass, even if a set lists it (checked when `allowlist.py` is imported). What this does and does not do: it guarantees nothing *from the UI process* reaches the child. The child `make` reads the repo-root `.env` itself (`mk/vars.mk`), exactly as in a terminal.

**Env modes (T3).** Both modes pass the same allow-listed environment; they differ in where AWS credentials may come from, and the mode is checked against the runner (`local` ⇔ `scrubbed`, `aws` ⇔ `dotenv`). `scrubbed`: `ENV=local` on the argv; no local target touches AWS, whatever `.env` holds (22 as built). `dotenv`: `ENV=aws` on the argv; the credentials (`AWS_PROFILE`, or the key pair; `AWS_REGION`) reach the child **only** through `make`'s own loader, `mk/vars.mk`, which reads the root `.env` (rejects `$` and `#`, strips CR, skips empty values) and exports every non-empty `KEY=value` to the recipe. **`envload.py` therefore calls `make`; it never sources `.env` and never parses its values.** `.env` is not shell (a value with a space would run a command under `set -a; . ./.env`), and `make` is what the runbook's terminal commands use, so tab and terminal see the same settings. Credentials in the UI's own environment (a shell's `AWS_PROFILE`, or the keys `make ops-ui` exported into the UI process) never reach a child: only `.env`'s do. `HOME` passes (base), so a profile named in `.env` resolves from `~/.aws`. For the probes, which are not `make` targets, the same loader is used by wrapping the probe's recipe in `make --eval`:

```
("make", "-s", "--no-print-directory", "ENV=<local|aws>", "--eval", "__ops_probe: ; @<recipe>", "__ops_probe")
```

The rule exists only on that command line (it is not in `mk/`, and `make help`/`docs-check` never see it); `<recipe>` is a constant in `ops/probes.py`. GNU make ≥ 3.82 (4.3 on the WSL machine).

**The gate (T4).** The aws runner's Run buttons, its POSTs and its probes are enabled only when every one of these holds, checked in this order; the first that fails is the reason, shown verbatim in the header, on every aws Run button (disabled), and as the 403 body of a POST. The copy buttons stay.

| # | Condition | Reason when it fails |
|---|---|---|
| G1 | The process is the host run: `DEMO_UI_PUBLISHED_LOOPBACK` is not `1` | "AWS runs never run in the container: use make ops-ui on the host" |
| G2 | `DEMO_UI_HOST` is exactly `127.0.0.1` (not `0.0.0.0`, `::1`, `localhost` or a LAN address, token or not) | "AWS runs need the UI on 127.0.0.1 (this one listens on <host>)" |
| G3 | `DEMO_UI_AWS_OPS` is exactly `1` in the UI's environment (the root `.env`, which `make` exports to the UI it starts, or `make ops-ui`) | "AWS runs are off: start the UI with make ops-ui (or DEMO_UI_AWS_OPS=1 in .env)" |
| G4 | `make` is on `PATH` and the checkout is found (as for the local runner) | "make not found" / "checkout not found" |
| G5 | The root `.env` exists in the checkout (`make config-check` passes without one) | "root .env not found: cp .env.example .env, then make config-check" |
| G6 | `make config-check` exits 0: argv `make -s --no-print-directory config-check ENV=local`, scrubbed env, 20 s timeout (it starts `uv`), stdout discarded; cached until the `.env` mtime changes or re-check is pressed | "make config-check failed: run it in a terminal" (plus its first `error:` line, which names a key or a line number and never a value, through `mask_secrets`) |

T4's three conditions are G1+G2 (bound to `127.0.0.1`, not the published-loopback container mode), G3 and G6; G4 and G5 are the prerequisites without which G6 cannot be asked. `ENV` does not enter the gate: `make ops-ui ENV=aws` and `ENV=local` both offer the aws runner (U3 still turns the *local* runner off with `ENV=aws`). The HX-Request check, the same-Origin check and the token cookie apply to every Ops POST as before. Credentials are not a gate condition: without them, the header says "account unknown: <probe reason>" and a run fails visibly in the log.

**Admin path `/32` (T2).** `aws-admin-open` takes one argument, the caller's address as a `/32`. The UI fills the field from the `checkip` probe (below) when the admin box renders with the gate on (cached 10 min); the presenter may type over it. The POST's `cidr` field is accepted only if `ipaddress.IPv4Network(value, strict=True)` parses it with prefix length 32 (a bare `a.b.c.d` gets `/32` appended first) and the address is global (`is_global`: not private, loopback, link-local, multicast, reserved or unspecified); the normalised `str(network)` is appended as `ADMIN_CIDR=<it>`. Anything else → 400 "not a public IPv4 /32", nothing runs. IPv6 is refused (the admin gate's list is IPv4 for this demo; 10 §2.1). `make admin-open` validates `ADMIN_CIDR` again before writing (below).

**`admin-open` / `admin-close` (new make targets, `mk/aws.mk`; 10 §5).** Each edits `deploy/terraform/envs/aws.tfvars` in place through `scripts/admin_cidr.py` (new), then runs `make plan`, then `make deploy`:
- The file must exist: absent → exit 2, "deploy/terraform/envs/aws.tfvars not found: copy envs/aws.tfvars.example first", nothing written (the `.example` is never edited).
- The one line `demo_admin_cidrs = …` is replaced by `demo_admin_cidrs = ["a.b.c.d/32"] # managed by make admin-open / admin-close` (open) or `demo_admin_cidrs = [] # managed by make admin-open / admin-close` (close). No such line → it is appended with the same marker comment. More than one, or a list spread over several lines → exit 2, "edit demo_admin_cidrs by hand to one line", nothing written. Every other byte of the file is kept; the write is atomic (temp file in the same directory, `os.replace`), mode kept.
- `admin-open` takes `ADMIN_CIDR`, or, when it is empty (a terminal run), the body of `curl -fsS --max-time 5 https://checkip.amazonaws.com` with `/32`; the script validates it with the rule above, then exits 2 on anything else. One address replaces the list (the gate's purpose is "your /32 only").
- After `make plan`, the recipe reads the summary line of `artifacts/terraform-plan.txt` (`scripts/admin_cidr.py plan-gate`, the regex of `ops/plan.py`; a Python port rather than a `grep`, so the rule is unit-tested in one place, step 2 of prompt 23): changing the list always replaces the bearer password, the mock task definition and its secret version, and the gate lets exactly that roll through (every destroyed or replaced address in `admin_cidr.ROLL`, and no more; it prints "rolls the demo admin bearer and the mock task (3 replaced); deploying"). If anything else would be destroyed and `FORCE` is not `1`, it stops with exit 3, "the plan destroys K resource(s) (changing demo_admin_cidrs replaces DEMO_ADMIN_BEARER and rolls the mock task): read artifacts/terraform-plan.txt, then `make deploy`". A summary it cannot read counts as destroying. Otherwise it runs `make deploy` (which re-runs `make outputs`). From the tab, an exit 3 ends the job green as `confirm` (no note; the gate's own three log lines are not shown), with step 4 showing the destroy chips and asking for `deploy` (T5).
- `admin-close` asks "close the demo admin path (plan, then deploy)? [y/N]" unless `FORCE=1`; with `FORCE=1` it also deploys through a plan that destroys (closing destroys the admin resources by design; the typed `close` is the confirmation). Answered `y` in a terminal without `FORCE=1`, a destroying plan stops with exit 3 as for open (the conservative reading: `y` confirms plan-then-deploy, not a destroy). From the tab: type `close`, then Run (FORCE=1 appended).

**Destructive steps (T5).** `aws-down` (`down`), `aws-down-all` (`down-all`), `aws-admin-close` (`close`) and `aws-deploy` when the last plan destroys anything or its summary cannot be read (`deploy`) have a text field in their row; Run enables (client side) only when the field holds the word, and the server compares again: the POST's `confirm` field, stripped of surrounding whitespace, must equal the word exactly (case-sensitive), else 400 "type <word> to confirm" and nothing runs. The word is compared, never passed to the child. Only then is `FORCE=1` appended (to the three whose recipes ask; `deploy` asks nothing). `aws-deploy` without destroys needs no word.

**Plan summary chips.** `ops/plan.py` parses the last match of `^(?:Plan: (?:(\d+) to import, )?(\d+) to add, (\d+) to change, (\d+) to destroy\.|No changes\.)` (ANSI already stripped; `No changes.` = 0/0/0). Shown as three chips, `+add ~change −destroy` (destroy coral when > 0), in two places: in the job's `ops-status` frame, from the streamed lines of any aws job that printed one (`aws-plan`, `aws-deploy`, `aws-admin-open`, `aws-admin-close`); and on step 3, from `artifacts/terraform-plan.txt` (written by `make plan` with `terraform show`). **Transcripts (T7).** Every aws-runner job is appended to `artifacts/ops-log/<YYYY-MM-DD>-<name>.log` (UTC date, `name` = the allowlist id, e.g. `2026-10-11-aws-deploy.log`; directory 0700, file 0600, gitignored by `artifacts/**`): a start line `== <ISO-8601 UTC> start <name>: <argv, with ADMIN_CIDR shown as <cidr>>`, every line exactly as it went to the browser (masked, then cut), a `== plan +A ~C -D` line when a summary was seen, and an end line `== <ISO-8601 UTC> end <pass|fail|stopped> exit <code> <seconds> s`. Local-runner jobs write nothing (22 unchanged). `transcript.last(name)` reads the newest file's last end line: the evidence of steps that leave no file of their own.

**Stop on the aws runner.** Terraform treats one interrupt as "finish the current operation, save state, stop" and a second as abort; a kill leaves the state lock held. So for aws jobs Stop sends SIGINT once to the process group and the badge says "stopping: terraform is saving state"; a second press sends SIGTERM; the UI never sends SIGKILL to an aws job: a grandchild still holding the pipe after the child exited gets SIGTERM, and on UI shutdown a running aws job gets SIGINT. (Local jobs keep SIGINT → 1.5 s SIGTERM → 2 s SIGKILL.)

**The runner (`ops/runner.py`).** `asyncio.create_subprocess_exec(*argv, cwd=<checkout root>, env=<above>, stdin=DEVNULL, stdout=PIPE, stderr=STDOUT, start_new_session=True)`. One job at a time, and never while a macro runs (one lock shared with §5's runner): a second `POST /ops/run/…` → 409 with the running job's name. Each output line is decoded (UTF-8, `replace`), stripped of ANSI escapes and control characters, passed through `redact.mask_secrets` (new) and then `redact.mask` (numbers, §8.3), and only then cut at 2,000 characters (as built: masking first, so a cut can never split a secret and leave half of it unmasked): `Bearer <x>` → `Bearer ••••`; `NAME=value` where `NAME` matches the deny patterns above → `NAME=••••`; `AKIA…`/`ASIA…` access-key ids; (T7, new) `aws_secret_access_key`, `aws_session_token` and `aws_access_key_id` in any case followed by `=` or `:` (quoted or not) → `<name>=••••`; a secret-shaped run, exactly 40 characters of `[A-Za-z0-9/+=]` bounded by characters outside that set and holding at least one upper-case letter, one lower-case letter and one digit, `/` or `+` (an AWS secret key; a 40-hex git sha has no upper case and survives); any run of 100 or more `[A-Za-z0-9/+=]` (session tokens); and any exact value ≥ 8 characters of the UI's own secrets (`TOWER_BEARER`, `MOCK_ADMIN_TOKEN`, `ALERTS_INTERNAL_BEARER`, `BIND_ADMIN_TOKEN`, `DEMO_UI_TOKEN`, `DEMO_ADMIN_BEARER`, every value in `deploy/compose/.env` and, new, in `deploy/.env.aws` whose key matches the deny patterns; both files are re-read when they change, because `make up` and `make outputs` write them during a job). The root `.env` is never read for this: its values reach no Python code (T3), so the patterns above are what masks them. Lines go out on the existing `GET /events` stream (O6: no second transport), batched every 200 ms as one `ops` frame (`ops_log.html`, swapped `beforeend`); the last 500 lines are kept for a page that connects mid-job. **Stop** (`POST /ops/stop`) sends SIGINT to the process group, SIGTERM after 1.5 s, SIGKILL at 2 s (pressed before the child exists, it waits for the spawn and then stops it); the badge then says `stopped`. When the child exits but a grandchild still holds the output pipe after 1 s, the group is killed: a job never outlives its badge. The end of a job is one `ops-status` frame: `pass` (exit 0), `fail` (exit ≠ 0) or `stopped`, with the exit code and the duration. A local job writes nothing to disk; an aws job appends its transcript (T7, above). Uvicorn's access log stays off. The aws runner differs only where this section says so: its Stop, its transcript, `FORCE=1`/`ADMIN_CIDR` after validation, and the plan chips in its `ops-status` frame.

**Asset rules**
- Vector only: inline or vendored SVG, no raster photos. No Alexa, Amazon or carrier logos or trade dress; the speaker is a plain cylinder with a light ring.
- No external URL anywhere in `templates/` or `static/` (no CDN, fonts, analytics or tracking). Fonts are vendored woff2 with the OFL `LICENSE`; the UI text uses `system-ui`, the display face only the title and the pane names.
- Page weight ≤ 600 KB for all of `static/` (66 KB today, 51 KB of it HTMX). First paint < 1 s on the laptop.
- Motion is 150–300 ms (the beam 600 ms). `prefers-reduced-motion: reduce` turns off transitions and keyframes but still applies the state classes (beacon colour, shield, health).
- Accessibility: Lighthouse/axe ≥ 95. Text contrast ≥ 4.5:1 on navy, with a visible focus ring. `aria-live="polite"` on `#run-status`, on the stepper and on one visually hidden feed announcer that `stage.js` writes the newest row into (the feed lanes are swapped whole, so they are not live regions themselves). ## 7. Wiring

**ENV=local (default).** One compose service `demo-ui` on the `tower` network, published on `127.0.0.1:8090`, with the scripted agent: this is what CI and `make demo` exercise. The judge-facing run is the UI on the host with Bedrock, `make showcase-ui`, against the same compose stack, on `127.0.0.1:8091` so that it and the container can be open side by side (S1, 2026-10-09: both on 8090 made `make up && make showcase-ui` fail with "address already in use"; the alternative, stopping the compose container, would change what `make up` leaves running). If the port is taken, `make showcase-ui` says so and exits 2; `SHOWCASE_UI_PORT=<port>` picks another. Every pane works. The phone that scans the QR code reaches the binding page at `BINDING_PUBLIC_URL`, as in `showcase-binding`; it never reaches the UI.

**ENV=aws.** The same container, or `uv run` (`make showcase-ui ENV=aws`), on the laptop, reading `deploy/.env.aws` itself (§6) with `ENV=aws`. Nothing is created in the account by the UI process itself; what the Ops tab's aws runner starts is the runbook's `make` targets, the same as a terminal (T2). The admin path (U2, 10 §2.1) is off by default; with `demo_admin_cidrs` set to the laptop's address and `make deploy` + `make outputs` run, `.env.aws` carries the admin URLs and `DEMO_ADMIN_BEARER`. What a laptop can reach:

| Pane | Admin path closed (default) | Admin path open (`demo_admin_cidrs` = your /32) |
|---|---|---|
| 1 Conversation | Tower on AgentCore Runtime with a valid JWT (D21: an empty discovery URL means every call is 401); Bedrock with the `att` profile. Asish only (decision 3) | the same; Moment 1–3 macros on, Transplant off with its caption (§5) |
| 2 Carrier | off: "admin path closed: see Ops → Admin path". The ALB forwards no `/_admin` path | works through `https://<api>/carrier-admin/_admin/*`: state (refs only; the gateway forces `view=refs`), clock, events by `ref`, faults, Reset (§3) |
| 3 Feed: audit | DynamoDB with the `att` profile (about 3 reads/s at 5 s polling) | the same |
| 3 Feed: SMS | "SMS list unavailable": `/internal/sent` is 404 (route absent); the SMS arrives on the real phone and the audit row with `message_ref` is the evidence | `GET /internal/sent` from `SentSms` (U1) |

Closing the path (`demo_admin_cidrs = []`, `make deploy`, which re-runs `make outputs`) removes the routes, the authorizer, the ALB rule, `SentSms`, the admin flags and the SSM copy of `DEMO_ADMIN_BEARER` (and the bearer itself), and rewrites `.env.aws` without it; the UI then shows the closed column again.

## 8. What it must never do

1. **Decide anything.** It imports nothing from `tower_policy` or `camara_client` and calls no CAMARA path. Outcome chips come only from Tower's `reason_codes` in the `ToolResult` and from the audit; the pass/fail badge compares those codes with the story's expected codes and decides nothing about the line.
2. **Call the carrier, or the carrier gateway.** Its only routes to the mock are under `/_admin`, which is a simulation aid and not CAMARA, locally or through the CIDR-gated admin path on AWS (which forwards only `/_admin` paths). It holds no Gateway URL or token.
3. **Show a phone number, or handle one.** Lines are shown by holder ("Asish", "Mom") and by the mock's opaque `ref`. The UI reads `/_admin/state?view=refs` and fires events by `ref` (G2), so no request it sends and no response it reads carries a number. As defence in depth, every HTML fragment and SSE frame goes through the number filter (`demo_ui.redact`) before it leaves the process. It masks with the shared phone-number rule `ref_client.privacy` (decision 1, 2026-10-11), the same rule the privacy tests' `phone_hits` uses: (a) `+` followed by 8 or more digits, with spaces, dots, dashes or parentheses between digit groups, is always a hit; (b) a bare run of 10 or more digits is a hit unless the *whole* token around it (letters, digits, `:.+-`) is on `DATE_TIME_ALLOWLIST` — ISO-8601 with or without separators, `T`, `Z` or an offset (`2026-10-05T14:12:00Z`, `20261005T141200Z`, `20261005141200`; without `T` the seconds are required) or 13-digit epoch milliseconds starting with `1`. Epoch seconds are not allowed (10 digits is a North-American national number), and a number glued to or beside a date is still a hit. On top of the rule, `GROUPED` masks bare North-American groupings (`(613) 555-0101`, `613.555.0101`, `1 613 555 0101`). Uvicorn runs with `access_log=False`; log lines carry event names and counts, never bodies.
4. **Write consent.** Grants and revokes go through the binding page (`/_admin/grants`, then `tower_consent`), which records them. The one direct store write is the local Reset, which reuses the `make seed` code (decision 5); on AWS Reset makes no store write of its own (U3: mock, Alerts and binding page over HTTP).
5. **Read another person's audit.** Only `list_for_line` as the line's owner. Pane 4 asks the binding page for `?table=Grants`, so no other table (and no Audit row) reaches the process: the build-log finding of the demo UI review (pane 4 received every line's Audit rows through `/_admin/tables`) is resolved (2026-10-11, `test_app.py::test_feed_tick_renders_every_pane_without_a_number`, `test_real_backends.py::test_revoke_from_the_grants_pane_flips_resolve_and_the_feed`).
6. **Speak first.** It has no way to make Alexa+ say anything. Proactive messages stay SMS from Alerts.
7. **Be deployed to AWS.** No ECR repository (`SERVICES` stays five for `push`; `build` adds the sixth image locally), no Terraform resource, `values-eks.yaml` `enabled: false`. The admin path is Terraform for the *product's* endpoints (10 §2.1); nothing of the UI is in it.
8. **Touch the hot path.** It is a client like the reference client. Tower's path still makes one consent read plus the carrier calls (and D2).
9. **Be depended on.** It is the only importer of `ref_client` outside the reference client, and nothing imports `demo_ui`: no product component (Tower, Alerts, the binding page, the mock, `packages/`) gains a model on its path through it (09 §4 "Who may depend on it"; `services/ref-client/tests/test_fallback.py`).
10. **Run anything but the allowlist.** No shell, no string from a request in a command (the confirm word is compared, never passed; the `/32` is validated and normalised before it is appended), no `ENV=eks` target, no `aws`/`terraform` call outside the aws runner's allowlisted targets and the read-only probes; the local runner never runs an `ENV=aws` target and runs nothing with `ENV=aws` (O1, U3). The aws runner runs only behind the gate (T4): never in the container, never on an address other than `127.0.0.1`, never without `DEMO_UI_AWS_OPS=1` and a passing `make config-check`. The child gets an allow-listed environment; its output reaches the browser and the transcripts only through `redact.mask_secrets` and `redact.mask`.
11. **Mutate AWS on a click alone.** AWS changes only through the aws runner's `make` targets, the same as the runbook's terminal commands, behind the gate; `down`, `down-all`, `admin-close` and a `deploy` whose plan destroys anything also need their typed word (T5). The UI's own code never calls an AWS API to change anything (no boto3 for Ops; the probes are read-only), never touches IAM or a table directly, and never reads an AWS key: the children get the credentials from the root `.env` through `make` (T3). The other AWS-side writes are, as before, the demo admin calls of panes 2 and 4 and Reset, through the CIDR-and-bearer path.
