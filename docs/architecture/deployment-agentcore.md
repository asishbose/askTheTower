This is the companion to [`diagrams/08-agentcore-deployment.drawio`](diagrams/08-agentcore-deployment.drawio).

differ, §2 says so.

**Web chat (prompt 20, designed and built 2026-10-09; validated offline, never applied).** `make deploy` also creates the Cognito pool (`modules/cognito`), the web chat agent as a second Runtime (`agentcore_runtime`, protocol HTTP), and the page on S3 + CloudFront with a Lambda function URL in front of the agent (`modules/web_chat`). Contract: [`components/09-reference-client.md`](components/09-reference-client.md) §6. Users and the page upload are step 10, after the apply. The code exists (`terraform validate` passes; `tests/aws/test_terraform_static.py` checks the names below); nothing of it has been planned or applied.

**Demo admin path (prompt 22, specified 2026-10-11; off by default, never applied).** With `demo_admin_cidrs` non-empty, `make deploy` adds CIDR-gated, bearer-protected routes on the existing public HTTP API so the laptop's demo UI can reach the mock's `/_admin`, Alerts' `/internal/sent` and `/internal/reset`, and the binding page's `/_admin` (bearer mode). Page 1 draws it dashed (A1). Names, status codes and teardown: [`components/10-scheduler-and-infra.md`](components/10-scheduler-and-infra.md) §2.1; the TODO(human) sequence: `docs/submission/build-log/22-ops.md`.

## 1. Install steps (mirrors page 2)

Settings come from the root `.env`, which `mk/vars.mk` exports. That includes the `ask-the-tower-dev` access
keys and any `TF_VAR_*`. `plan`, `deploy` and `down` add `-var-file=envs/aws.tfvars` when that file exists
(`ecr-up` and `down-all` pass the same file to the ECR root). `plan` and `deploy` add `-var=image_tag=$(IMAGE_TAG)`:
the tag the last `make push` completed (`artifacts/image-tag`), else the git sha. `down` passes no `image_tag`.

### Step 1 — Credentials, state backend, tfvars · `TODO(human)` build-log/13 (state backend; tfvars)
- **Command:** `aws configure --profile att`, or put the keys in the root `.env`. Then `aws sts get-caller-identity`.
- **Artefact:** `deploy/terraform/backend.tf` (bootstrap commands in its header), `deploy/terraform/envs/aws.tfvars.example`, `make config-check`.
- **Preconditions:** an IAM user with admin rights for the hackathon window, and a public Route 53 zone you own for `mock_domain_name`, or an existing ACM certificate.
- **Result:** an S3 state bucket (versioned, KMS-encrypted, private) and a lock table, both created by hand and outside Terraform. Plus `envs/aws.tfvars` (gitignored) with `mock_domain_name` and `mock_route53_zone_id`. `tower_jwt_*` are no longer needed: Tower's issuer, JWKS and client id come from `modules/cognito` (they remain as overrides for a hand-made pool).
- **Rollback:** delete the bucket and lock table by hand, last of all (§5).

### Step 2 — `make ecr-up` · `TODO(human)` build-log/13 (images)
- **Command:** `make ecr-up` (once; idempotent — a re-run reports no changes).
- **Artefact:** `deploy/terraform/ecr/`, a separate root with its own state key (`ask-the-tower/ecr/terraform.tfstate`): `aws_ecr_repository.service` ×5 plus `aws_ecr_lifecycle_policy.service` (keep the last 10, scan on push, AES256, `force_delete`). The main root reads the repositories with `data "aws_ecr_repository"` and never manages them.
- **Preconditions:** step 1. `terraform init` has to succeed against the backend. If the repositories were already created with the old `-target` apply in the main state, move them first (`deploy/terraform/README.md`, "Migrating repositories").
- **Result:** five empty repositories, `att-dev/{tower-mcp,mock-carrier,binding-page,alerts,ref-client}`, and `artifacts/tf-outputs-ecr.json` (`ecr_repositories`, `registry`, `region`), which `make push` reads until the first deploy writes `artifacts/tf-outputs.json`.
- **Rollback:** `make down-all` (after judging). `make down ENV=aws` keeps them.

### Step 3 — `make build`
- **Command:** `make build` (one image: `make build-tower-mcp`).
- **Artefact:** `mk/build.mk`. It runs `docker build -f services/<svc>/Dockerfile -t ask-the-tower/<svc>:<sha>,latest .` for each of the five services.
- **Result:** local host-architecture images. Nothing changes in AWS. `make push` rebuilds for arm64, so these images are not the ones AWS runs (finding F3). The step is still useful for `make sbom` and `make scan`.
- **Rollback:** `docker image rm`.

### Step 4 — `make push ENV=aws` · `TODO(human)` build-log/13 (images; dry run only so far)
- **Command:** `make push ENV=aws`.
- **Artefact:** `scripts/push_images.py`. It runs `aws ecr get-login-password | docker login`, then for each service `docker buildx build --platform linux/arm64 --provenance=false --sbom=false -t <repo>:<sha> -t <repo>:latest --push .` On success `make push` writes the sha to `artifacts/image-tag`.
- **Preconditions:** step 2's `artifacts/tf-outputs-ecr.json` (or a later `artifacts/tf-outputs.json`), `docker buildx`, QEMU binfmt for arm64 on an amd64 laptop, and a clean commit (the tag is `git rev-parse --short HEAD`).
- **Result:** 5 single-manifest linux/arm64 images × 2 tags (no attestation index), scanned on push.
- **Rollback:** `aws ecr batch-delete-image`; `make down-all` removes the repositories.

### Step 5 — `make plan` · `TODO(human)` build-log/13
- **Command:** `make plan`. It prints and uses the tag step 4 recorded, so a commit in between no longer matters (F6, resolved).
- **Artefact:** `mk/aws.mk`. It runs `terraform init`, then `plan -out artifacts/tfplan`, then `show > artifacts/terraform-plan.txt`.
- **Result:** nothing changes in AWS. Review the plan.

### Step 6 — `make deploy` · `TODO(human)` build-log/13
- **Command:** `make deploy`. It runs `apply -auto-approve`, then outputs → register-gateway → seed-aws → outputs, which are steps 7–9.
- **Artefact:** `deploy/terraform/main.tf` and `modules/*`.
- **Creation order** (Terraform's resource graph; module boundaries are not barriers):
  1. `random_password` ×5; `network` (VPC, 2 public and 2 private subnets, IGW, S3/DynamoDB gateway endpoints, egress SG, VPC link); IAM roles.
  2. `kms` (its key policy names the Runtime and Lambda roles); then `dynamodb` (7 tables), the SNS topics and the mock's Secrets Manager registry.
  3. `lambdas` edge: HTTP API, CloudFront and WAF. This yields `public_base_url`.
  4. `mock_carrier`: ACM certificate and Route 53 validation, then the internal ALB and listener, then the ECS cluster, task definition and service.
  5. `agentcore_identity`: two OAuth2 credential providers (token URL = the mock) and the binding workload identity (return URL = `public_base_url`).
  6. `agentcore_gateway`: the Gateway, then 6 OpenAPI targets.
  7. `cognito` (pool, Hosted UI domain, app client `web-chat`; its callback URL needs the `web_chat` CloudFront domain, which needs nothing from Cognito). Then `agentcore_runtime`: Tower (needs the Gateway ARN and URL, KMS, the tables and the Cognito issuer/client) and, with `enable_web_chat`, the agent runtime `ref_client` (its own role, needs Tower's URL and Cognito). Then the 3 Lambda functions (need the Gateway URL and the SNS topic), the authorize route over the VPC link, and the `web_chat` Lambda URL proxy (needs the agent runtime ARN; CORS = the CloudFront origin). Resource-level there is no cycle: CloudFront → Cognito client → runtimes → proxy.
  8. The SNS subscription, `scheduler` (6 schedules) and `observability`.
- **Preconditions:** steps 1–5. The images for `image_tag` must exist: the Lambda functions, the Runtime and the ECS service all reference them at create time, so `make deploy` first runs `push_images.py --verify` (`aws ecr describe-images` per repository) and stops before `apply` if any is missing.
- **Result:** everything on page 1.
- **Rollback:** `make down ENV=aws`. A failed apply leaves partial state. Re-running `make deploy` converges, or `make down` clears it.

### Step 7 — `make register-gateway` (inside step 6) · `TODO(human)` build-log/13 (verify the Gateway contract)
- **Artefact:** `scripts/register_gateway.py`. It **registers nothing**: Terraform created the targets in step 6. The script lists the deployed tools over MCP (signed with SigV4), maps them with `camara_client.resolve_tool_names` and writes `artifacts/gateway-tools.json`. `--check` diffs against the file.
- **Result:** no AWS change. Services resolve the same names at warm-up (`CARRIER_GATEWAY_TOOLS=discover`).
- **Rollback:** none needed.

### Step 8 — `make seed-aws` (inside step 6) · `TODO(human)` build-log/13
- **Artefact:** `scripts/aws_seed.py`.
  1. `ecs list-tasks`, then `ecs execute-command` into the mock task, running `POST 127.0.0.1:8443/_admin/scenarios/load {"name":"demo"}`. The ALB never forwards `/_admin`.
  2. `aws_seed.seed_people` (`tower_consent` over boto3, with KMS `GenerateMac` and `Encrypt`). It writes the users, Mom's line and Mom → Asish `watch`, under the **Cognito `sub`s** (D-F): `--user asish=<sub> --user mom=<sub>`, or `artifacts/cognito-users.json` from `make cognito-users`. Without either it reloads the mock, skips the consent rows and prints "run `make cognito-users`, then `make seed-aws`" (exit 0, so the `make deploy` chain still finishes). It never writes the local names `user-asish` / `user-mom` on AWS (it refuses a `user-…` value). It binds **Mom's** line and the Mom → Asish grant and leaves **Asish's line unbound**, so Flow 1 of `bind-and-alert-flows.md` (NOT_BOUND → link → one tap → ask again) can be filmed; `make seed-aws SEED_ARGS=--bind-asish` binds it too, for `make demo ENV=aws`.
  The script is idempotent.
- **Preconditions:** the AWS CLI with the Session Manager plugin, a running mock task, and `artifacts/tf-outputs.json`.
- **Result:** the mock is reset to `scenarios/demo.yaml`, and the consent tables hold the demo rows.
- **Rollback:** re-run it (idempotent), or `make down`.

### Step 9 — `make outputs` (runs twice inside step 6)
- **Artefact:** `mk/aws.mk` runs `terraform output -json > artifacts/tf-outputs.json`. `scripts/render_env.py --env aws` then writes `deploy/.env.aws`. That file holds `TOWER_URL`, `BINDING_URL`, `ALERTS_URL`, `CARRIER_GATEWAY_URL`, `WEB_CHAT_URL`, the table prefix and the KMS ARNs. With the demo admin path closed (the default) it holds no secrets. Open, it also holds `MOCK_URL`, `BINDING_ADMIN_URL` and `DEMO_ADMIN_BEARER` (the one admin bearer, decision 1 of 2026-10-11; never the Alerts internal bearer), read from SSM by the script and never printed (10 §2.1); the outputs JSON holds only the parameter names. `mk/vars.mk` includes it for every `ENV=aws` target.
- **Rollback:** delete the two files.

### Step 10 — Web chat users and page · `TODO(human)` build-log/20
- **Command:** `make cognito-users` → `make seed-aws` → `make web-chat-sync` → `make web-chat-url`.
  1. `make cognito-users` runs `scripts/cognito_user.py create asish` and `create mom` (`admin_create_user` + `admin_set_user_password --permanent`). The password comes from `COGNITO_PASSWORD_ASISH` / `COGNITO_PASSWORD_MOM` in the root `.env`, or a prompt; it is never written to disk. It writes `artifacts/cognito-users.json` (`{name: sub}`, gitignored).
  2. `make seed-aws` writes those `sub`s into `Lines` and `Grants` (step 8).
  3. `make web-chat-sync` (`scripts/web_chat_sync.py`; `--dry-run` touches nothing) renders `config.js` from the outputs (`cognito_hosted_ui_url`, `cognito_client_id`, `web_chat_url`, `agent_url`, `binding_url`), uploads `services/web-chat/` to `web_chat_bucket` and invalidates `web_chat_distribution_id`.
  4. `make web-chat-url` prints the page URL. Sign in as `asish` in one browser profile and as `mom` in another.
- **Preconditions:** step 6 with `enable_web_chat = true` (the default). The Hosted UI callback URL is the CloudFront URL; Terraform sets it, so nothing is typed in the console. Verify the demo phone in the SNS SMS sandbox (output `sms_sandbox_commands`). Binding against the Fargate mock needs `mock_assume_mobile_data = true` (the default; 08 §3); or film the bind locally.
- **Unverified:** whether a function URL with `auth_type NONE` also needs a `lambda:InvokeFunction` permission in this account (Terraform adds only `lambda:InvokeFunctionUrl`); whether the Runtime HTTP protocol needs `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id` from a JWT caller (the page sends one, ≥ 33 characters, and the proxy forwards it), and whether the JWT authorizer passes `Authorization` through to the container with `request_header_allowlist`.
- **Result:** two Cognito users, the demo rows under their `sub`s, and the page live at `web_chat_url`.
- **Rollback:** `uv run python scripts/cognito_user.py delete <name>`; `make down ENV=aws` removes the pool, users, bucket (force-destroy) and distribution.

## 3. Findings

These are also tracked as `TODO(human)` items in the build log, kept outside the repo. F1, F2, F4 and F6 were fixed by
the ECR-root split (2026-10-09; validated offline, not yet applied); the rest are open.

- **F1 — Merge drift. Resolved.** `ecr-up`, `ecr-outputs` and `down-all` are in `mk/aws.mk` and `make help`; `make docs-check` passes.
- **F2 — Bootstrap chicken-and-egg. Resolved.** `make ecr-up` writes `artifacts/tf-outputs-ecr.json`, and `push_images.py` falls back to it when `artifacts/tf-outputs.json` has no `ecr_repositories`; no `-target` apply.
- **F3 — `make build` is not what gets pushed.** It builds host-arch images, and `push_images.py` rebuilds with buildx for arm64.
- **F4 — Lambda and buildx attestations. Resolved (pre-emptively).** `push_images.py` passes `--provenance=false --sbom=false`, so each tag is a single linux/arm64 manifest, not an OCI index. Confirm on the first `CreateFunction`.
- **F5 — `register-gateway` registers nothing.** Terraform does the registration. The target's help text should say "list the Gateway's tools and write `artifacts/gateway-tools.json`".
- **F6 — Tag drift. Resolved.** `make push` records the pushed tag in `artifacts/image-tag`; `plan` and `deploy` use it (`IMAGE_TAG=` overrides) and `deploy` verifies it in ECR before `apply`; `down` passes no `image_tag`.
- **F7 — `render_env.py` writes `CARRIER_CLIENT=gateway` unconditionally**, even when `tower_carrier_client = "direct"`. No output carries that choice.
- **F8 — Env vars missing from every `services/*/.env.example`** (marked † on page 3). Set by Terraform: `CARRIER_GATEWAY_AUTH`, `CARRIER_GATEWAY_REGION`, `TOWER_TRACE_LOG_GROUP`, `TOWER_METRICS_NAMESPACE`, `TOWER_RECONCILE_WINDOW_H`, `MOCK_CLIENTS_YAML` (ECS secret). Also, `tower-mcp`'s `.env.example` lacks `TOWER_KMS_KEY_ID`, `TOWER_KMS_HMAC_KEY_ID` and `CARRIER_SCOPES`, which Terraform sets for it; they appear only in binding-page's.

Resolved in code by prompt 20 (not yet applied):** the image's default command becomes the HTTP app (`/invocations`, `/ping` on 8080), the runtime gets its own role, and `enable_web_chat` replaces `enable_ref_client_runtime`. ## 5. Teardown order

`make down ENV=aws` runs `terraform destroy` on the main root, which goes in reverse dependency order:

1. `observability` (alarms, filters, dashboard), `scheduler` (6 schedules, group, role), the SNS subscription and its Lambda permission.
2. The Runtimes (`tower`, and the web chat agent `ref_client`) with their log groups; the `web_chat` Lambda URL proxy, the CloudFront distribution and the S3 bucket (`force_destroy`); the Cognito app client, domain, users and pool; the 3 Lambda functions with their log groups; the HTTP API routes and integrations, including the authorize route.
3. The Gateway targets, then the Gateway and its role; then the Identity credential providers and workload identity.
4. The ECS service, then the task definition and cluster; the ALB listener, rules, target group and ALB; the Route 53 record, ACM validation and certificate.
5. CloudFront and the WAF web ACL (slow: disable, then delete); the HTTP API and its stage.
6. The SNS topics and SMS preferences; the Secrets Manager registry (0-day recovery); the DynamoDB tables (PITR backups go with the Audit table).
7. The KMS keys, which enter a 7-day `PendingDeletion` window (they are not deleted at once), and their aliases. Then the IAM roles and policies.
8. `network`: the VPC link, SGs, endpoints, subnets, route tables, IGW and VPC. The `random_password` values. **Not** the ECR repositories: they are in the ECR root and stay, with their images, until `make down-all`.
9. Then `compose down -v` (local).

**Left behind by design, to remove by hand in this order:**
1. SMS sandbox numbers (`aws sns delete-sms-sandbox-phone-number`).
2. The Alexa `alexa-link` app client only if the pool was made by hand (registration.md §9); the Terraform pool goes with `make down`.
3. The Transaction Search setting.
4. Log groups that AWS created itself (for example `aws/spans`).
5. The Route 53 zone, if it was made only for this.
6. Finally, the S3 state bucket and lock table.

Then confirm with `aws resourcegroupstaggingapi get-resources --tag-filters Key=project,Values=ask-the-tower`:
after `make down` only the five `att-dev/*` repositories (tag `stack=ecr`) should remain; after `make down-all`,
nothing. The EKS root (`make down-eks`) is independent and must go first if it is up, because it reads this root's
state and places nodes in its subnets; `make down-all` does that order (EKS → main → ECR). Destroying the ECR root
before the main root would make the main root's destroy fail on its `aws_ecr_repository` data source.
