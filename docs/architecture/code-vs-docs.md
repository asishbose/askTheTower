## Top three

1. **D4 (resolved).** If one carrier call failed, the answer could still be "Your line is as it was." A SIM-swap timeout with call forwarding `none` passed the policy as `OK`. Now it is `CARRIER_ERROR` (or `STALE_DATA` from the Watch on a timeout).
2. **D7 (revoke resolved; grant open).** Revoking a grant left the grantee's Watch enabled and the carrier subscriptions on the line live, renewed by the watchdog. Now revoke disables that Watch and the watchdog drops the subscriptions. Granting still creates no Watch.
3. **D9 + D8 (resolved 2026-10-09).** The transplant profile and acknowledged escalation couldn't be reached from any product path. Now the line-holder sets the profile and contacts on the binding page ([04 §9](components/04-consent-and-binding.md), [06 §11](components/06-alerts-service.md)); "watch my line" keeps them, and the demo's transplant story saves them in a Settings step.

## Decision 2026-10-09 — NOT_BOUND vs NO_CONSENT (D18 follow-up)

An alias that does not resolve for the caller is `NO_CONSENT`, never `NOT_BOUND`. `NOT_BOUND` is reserved for the caller's own line being unbound, and only it carries the binding URL. Resolve: `"self"` with no Line → `bound=False`; an alias with no live Grant → `bound=True, grant="none"`; policy refuses before any carrier call in both cases ([04 §5](components/04-consent-and-binding.md)). Tests: `services/tower-mcp/tests/test_server.py::test_user_header_is_the_identity` asserts `NO_CONSENT`; unit cases `packages/tower-policy/tests/test_order.py::test_self_with_no_line_is_not_bound` and `::test_alias_with_no_live_grant_is_no_consent`. `testing-and-showcase.md` §2 script updated to match.

## Decision 2026-10-11 — masking (human decision 1)

One phone-number rule, defined in `tests/privacy/patterns.py` (`PLUS_NUMBER`, `DIGIT_RUN`, `DATE_TIME_ALLOWLIST`, `phone_spans`, `phone_hits`), with one runtime copy, `ref_client.privacy`, for the demo UI's output filter (`demo_ui.redact`, [11 §8.3](components/11-demo-ui.md)) since images carry no `tests/`; `tests/privacy/test_phone_rule.py::test_the_runtime_copy_is_this_rule` holds the two identical. `+` followed by 8–15 digits, grouped by spaces, dots, dashes or parentheses, is always a hit; a bare run holding a 10–15 digit match is a hit (a longer run is covered whole) unless its whole token is on `DATE_TIME_ALLOWLIST` (ISO-8601 with or without separators, `T`, `Z` or offset — without `T` the seconds are required — and 13-digit epoch-ms starting with `1`; epoch seconds are not allowed). The conventions' `\+?\d{10,15}` stays verbatim as `E164_STRICT` and as the ref-client's runtime gate (`transcript.E164`, now combined with the shared rule in `redact` and `has_number`, [09 §6](components/09-reference-client.md) rule 2). Product runtime checks (Tower auth, the audit record: any `\d{10,}`) are unchanged and stricter. `scripts/secrets_grep.py` uses the rule's spans. Tests: `tests/privacy/test_phone_rule.py`, `services/ref-client/tests/test_privacy_rule.py`, `tests/unit/test_privacy_single_source.py::test_phone_hits_is_the_shared_rule`; the four `services/demo-ui/tests/test_redact.py::test_grouped_numbers_are_masked` cases pass unchanged. Build log: `docs/submission/build-log/22.md` "Decision 1 — masking".

## Decision 2026-10-11 — audit TTL follows event time

`AuditRecord.ttl` = `ts + 90 d` stays on the writer's service clock (simulated locally), unlike every other TTL attribute, which is wall-clock ([06 §7 "Clocks"](components/06-alerts-service.md)). Deliberate: `ttl` is in the hashed row and `verify` uses it for chain lapse; the 90-day margin absorbs the simulated offset; on AWS event time is wall time. Doc: [07 §5](components/07-audit-log.md). No code change.
