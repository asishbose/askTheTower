# deploy/terraform — the AWS column

Terraform for the AWS hosting target of `docs/architecture/components/10-scheduler-and-infra.md` §1: Tower on
Bedrock AgentCore Runtime, carrier calls through AgentCore Gateway with AgentCore Identity holding the OAuth
clients, the mock carrier on Fargate behind an internal ALB, the binding page and Alerts on Lambda behind an HTTP
API (with CloudFront and WAF), EventBridge Scheduler, SNS, DynamoDB, KMS and a CloudWatch dashboard.

The same five images run here, on compose and on EKS. Only configuration differs.

Deployment architecture, step by step: [`docs/architecture/deployment-agentcore.md`](../../docs/architecture/deployment-agentcore.md) and its diagram
`docs/architecture/diagrams/08-agentcore-deployment.drawio`. They cover what each step installs, the creation and teardown order,
the config path of every integration, and where this root differs from prompt 13.

**Status (autonomous build, 2026-10-06):** written, `terraform fmt` clean, and `terraform validate` passes with
`init -backend=false` (AWS provider 6.67.0). It has never been planned or applied, because there were no AWS
credentials. Everything below marked *unverified* is an assumption that the first `make plan` / `make deploy`
has to confirm.

## Layout

```
ecr/               SEPARATE ROOT, own state: the five ECR repositories + lifecycle policy (`make ecr-up`; kept by
                   `make down`; destroyed only by `make down-all`). Outputs ecr_repositories, registry, region.
main.tf            module wiring, ECR read by `data "aws_ecr_repository"`, generated (non-carrier) secrets
providers.tf       aws (+ us-east-1 alias for the CloudFront WAF), random, archive (zips the web chat proxy)
variables.tf       every input; envs/aws.tfvars.example shows the ones a human sets
outputs.tf         Tower MCP URL, binding URL, hooks base, Gateway URL, ECR, tables, keys, ...
backend.tf         S3 state; placeholders (REPLACE-ME) and the bootstrap commands
tables.auto.tfvars.json   generated by modules/dynamodb/generate.py — do not edit
modules/
  dynamodb/        7 tables from data (Users, Lines, Grants, Watches, Audit+PITR, BindTokens+TTL, AlertsState+TTL)
  kms/             two keys: symmetric (msisdn_enc envelope, rotation on) + HMAC_256 (line_id, audit trim marker)
  network/         VPC, public/private subnets, optional NAT, S3/DynamoDB gateway endpoints, VPC link, egress SG
  mock_carrier/    Fargate service, internal ALB (HTTPS, ACM), Route 53 record, Secrets Manager for the mock's registry
  agentcore_runtime/   Tower (MCP protocol, JWT authorizer) + the web chat agent (HTTP protocol, own role:
                       Bedrock + logs + ECR only; enable_web_chat), log groups, IAM
  agentcore_gateway/   Gateway (AWS_IAM inbound) + one OpenAPI target per specs/camara/*.yaml, OAuth via Identity
  agentcore_identity/  two CustomOauth2 credential providers (client credentials; auth code) + binding workload identity
  lambdas/         binding-page, alerts, reconcile (arm64 images), HTTP API, CloudFront + WAF rate rule on /hooks/*
  scheduler/       transplant 5 min, care 30 min, daily 08:00 self + care, reconcile 03:00, escalation tick 5 min
  sns/             SMS replies topic → alerts Lambda, optional push topic, SMS preferences
  cognito/         user pool (admin-create-only), Hosted UI domain, app client `web-chat` (code + PKCE, no secret);
                   Tower and both Runtime authorizers trust it (tower_jwt_* are overrides only)
  web_chat/        the chat page: private S3 + CloudFront (OAC), Lambda function URL proxy → agent runtime (09 §6)
  observability/   dashboard (p95 per tool, alert counts, reconcile misses), metric filters, alarms, line_id guard
```

Three roots, three state keys in the same bucket: `ask-the-tower/ecr/…` (`ecr/`), `ask-the-tower/aws/…` (this
directory) and `ask-the-tower/eks/…` (`eks/`). The EKS target (prompt 14) reads this stack's outputs (tables, KMS
keys, SNS topic, subnets), so `make down ENV=aws` and `make down-eks` never destroy each other's resources; this
root reads the ECR repositories by name, so `make down ENV=aws` never deletes images. Teardown order is EKS → main →
ECR (`make down-all` does exactly that): the main root's destroy still reads the repositories, and EKS nodes sit in
the main root's subnets.

## Run

```bash
cp deploy/terraform/envs/aws.tfvars.example deploy/terraform/envs/aws.tfvars   # fill it in (gitignored)
# one-time: create the state bucket + lock table (commands in backend.tf), then edit the three backend.tf files
# (main, ecr/, eks/) or pass -backend-config
make ecr-up                              # once: five repositories (own state) → artifacts/tf-outputs-ecr.json
make build && make push ENV=aws          # five arm64 images → ECR, tags <sha> + latest; records artifacts/image-tag
make plan ENV=aws                        # → artifacts/terraform-plan.txt (image_tag = the recorded tag)
make deploy ENV=aws                      # verify tag in ECR → apply → outputs → register-gateway → seed-aws → outputs
make latency-aws                         # → artifacts/latency-aws.md (needs TOWER_JWT)
make down ENV=aws                        # destroy the main root; ECR repositories and images stay
make down-all                            # after judging only: down-eks (if up) + down + destroy the ECR root
make tf-check                            # offline: fmt, validate main + ecr (-backend=false), tables file current
```

`make push` reads `ecr_repositories` from `artifacts/tf-outputs.json` (main root, after a deploy) or, before the
first deploy, from `artifacts/tf-outputs-ecr.json`. Images are pushed with `--provenance=false --sbom=false`, so
each tag is a single linux/arm64 manifest (Lambda and AgentCore Runtime do not take an OCI index); `make sbom`
produces the SBOMs locally. `plan` and `deploy` use the tag the last `make push` completed (`artifacts/image-tag`,
falling back to the git sha; `IMAGE_TAG=<tag>` overrides), and `deploy` first checks with
`aws ecr describe-images` that every repository has it. `down` passes no `image_tag`: destroy does not need one.

### Migrating repositories created in the main state

Before this split, the repositories were `aws_ecr_repository.service` / `aws_ecr_lifecycle_policy.service` in
this root. **If you never applied this root (not even `-target`), there is nothing to do: run `make ecr-up`.**

If you did (`terraform apply -target=aws_ecr_repository.service`, as the old README said), move the ten objects
into the ECR root's state **before** any `make plan` / `make deploy` with the new code — otherwise this root plans
to destroy them, and with `force_delete` the images go too. `-state-out` only works with local state files, so
pull the main state into a temporary directory outside the repo (it holds generated secrets), move there, and push
both back:

```bash
terraform -chdir=deploy/terraform init -input=false            # main root, S3 backend
terraform -chdir=deploy/terraform/ecr init -input=false        # ECR root, S3 backend, still empty
W=$(mktemp -d) && terraform -chdir=deploy/terraform state pull > "$W/main.tfstate" && cd "$W"   # no .tf here
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_repository.service["tower-mcp"]'    'aws_ecr_repository.service["tower-mcp"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_repository.service["mock-carrier"]' 'aws_ecr_repository.service["mock-carrier"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_repository.service["binding-page"]' 'aws_ecr_repository.service["binding-page"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_repository.service["alerts"]'       'aws_ecr_repository.service["alerts"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_repository.service["ref-client"]'   'aws_ecr_repository.service["ref-client"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_lifecycle_policy.service["tower-mcp"]'    'aws_ecr_lifecycle_policy.service["tower-mcp"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_lifecycle_policy.service["mock-carrier"]' 'aws_ecr_lifecycle_policy.service["mock-carrier"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_lifecycle_policy.service["binding-page"]' 'aws_ecr_lifecycle_policy.service["binding-page"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_lifecycle_policy.service["alerts"]'       'aws_ecr_lifecycle_policy.service["alerts"]'
terraform state mv -state=main.tfstate -state-out=ecr.tfstate 'aws_ecr_lifecycle_policy.service["ref-client"]'   'aws_ecr_lifecycle_policy.service["ref-client"]'
cd - && terraform -chdir=deploy/terraform/ecr state push "$W/ecr.tfstate"
terraform -chdir=deploy/terraform state push "$W/main.tfstate" && rm -rf "$W"
make ecr-up                                                     # expect: No changes (then writes tf-outputs-ecr.json)
make plan                                                       # expect: no aws_ecr_* destroy in terraform-plan.txt
```

Without moving state, the same end result: `terraform -chdir=deploy/terraform state rm aws_ecr_repository.service
aws_ecr_lifecycle_policy.service`, then in `ecr/` `terraform import 'aws_ecr_repository.service["<svc>"]'
att-dev/<svc>` and `terraform import 'aws_ecr_lifecycle_policy.service["<svc>"]' att-dev/<svc>` for the five
services (add `-var-file=../envs/aws.tfvars` if it changes `name_prefix`/`environment`). Either way, `make ecr-up`
on repositories that exist but are in no state fails with `RepositoryAlreadyExistsException`.

`make deploy` prints the Tower MCP URL (AgentCore Runtime invocation URL, `qualifier=DEFAULT`), the binding URL
and the hooks base, and writes `deploy/.env.aws` for `make demo ENV=aws` / `make test-e2e ENV=aws`.

## Decisions and why

- **Gateway → mock.** The mock's ALB is internal. Gateway and Identity reach it through a *managed VPC resource*
  (`private_endpoint` on the target and on the credential provider). The phone reaches only the mock's
  `/oauth2/authorize`, through `GET /carrier/oauth2/authorize` on the HTTP API, which forwards over the VPC link.
  The ALB never forwards `/_admin/*`. `scripts/aws_seed.py` reaches it from inside the task with ECS Exec.
- **TLS on the mock.** Gateway and Identity call HTTPS endpoints, so the ALB needs a certificate for
  `mock_domain_name`. The default is ACM with DNS validation in a public Route 53 zone you own; the record then
  resolves to the ALB's private IPs. You can pass `mock_certificate_arn` instead. A private CA would avoid the
  public name but costs more than the rest of the demo combined, so it is not used.
- **Carrier credentials.** They live in AgentCore Identity only. With the mock, the mock *issues* them: its own
  registry is in Secrets Manager (10 §4), and the generated secrets are also given to Identity. Nothing
  carrier-side is in any service's environment on the Gateway path. `tests/aws/test_terraform_static.py` asserts
  this, plus no inline secrets in `.tf`. The cut-line configuration (`tower_carrier_client = "direct"`) is the
  one exception: Identity is not in use there, so Tower's client secret is Runtime config.
- **Secrets in state.** Terraform 1.9 has no write-only attributes. The generated client secrets, the Tower →
  Alerts bearer and the binding session key are therefore in state. State is private, versioned and
  KMS-encrypted in S3, and never committed. With Terraform ≥ 1.11, switch the Identity providers to
  `client_secret_wo`.
- **KMS: two keys, not one.** `line_id` is HMAC-SHA256 computed inside KMS (`GenerateMac`), which needs an
  `HMAC_256` key. `msisdn_enc` needs a symmetric key. KMS does not rotate HMAC keys, and rotating one would change
  every `line_id` anyway. 10 §2 is updated.
- **WAF.** WAF cannot attach to an HTTP API, so CloudFront (already in 10 §1 for the binding page) carries the
  web ACL. Its rate-based rule is scoped down to `/hooks/*`. API Gateway route throttling on `/hooks/*` applies
  either way. Turn both off with `enable_cloudfront_waf = false`.
- **No NAT by default.** The Fargate task runs in a public subnet with a public IP. Its security group admits
  only the ALB. Lambdas and Runtime are not in the VPC on the Gateway path. A NAT gateway (`enable_nat_gateway`)
  is needed only for the cut line.
- **Lambda images.** Lambda uses the compose images and enters them with `python -m awslambdaric <handler>`
  (`awslambdaric` is a dependency of alerts and binding-page). Reconcile uses the alerts image with
  `tower_audit.aws.reconcile_handler`.
- **Schedules.** These are the ones in 10 §3. The daily 08:00 polls use one timezone (`alerts_timezone`), which
  is enough at demo scale. A 5-minute escalation tick drives 06 §3's 15-minute escalation. The reconcile job's
  `now` is Scheduler's `<aws.scheduler.scheduled-time>`, so packages never read a clock.
- **Tool names.** AgentCore names tools `<target>___<operationId>`. Targets are named after the spec files.
  Services use `CARRIER_GATEWAY_TOOLS=discover`, and `make register-gateway` writes
  `artifacts/gateway-tools.json` as the record.
- **Metrics.** No metric carries a per-line label. A metric filter counts EMF records that mention `line_id`,
  and an alarm fires on any. A test checks the dashboard and every metric filter.

## Unverified (first apply must confirm)

- The Gateway tool-call contract assumed by `GatewayClient`: arguments `{body, <path params>}`, and errors as
  `isError` with `{status, body}`. AgentCore may instead flatten request-body fields into the tool input, or
  return the carrier error differently. Check one `tools/list` input schema and one 4xx.
- The Number Verification auth-code path through Gateway and Identity (`AUTHORIZATION_CODE` grant,
  `default_return_url`). If it does not fit the bind flow, set `binding_carrier_client = "direct"` (05 §3, the
  CIBA precedent).
- Whether Gateway accepts the CAMARA specs as-is. They are 15–61 KB inline. If Gateway rejects a construct or
  the size, move the payload to S3 (`open_api_schema.s3`) or strip the construct in the module's `payloads`
  local.
- Gateway/Identity `private_endpoint` with `routing_domain = mock_domain_name`.
- The Runtime `Authorization` header allowlist, so Tower can re-verify the JWT.
- Dashboard metric names for Runtime (`AWS/Bedrock-AgentCore` `Latency`).
- Reconciliation needs Tower's spans in `aws/spans`. Enable CloudWatch Transaction Search once per account, and
  run Tower under the ADOT distro (`aws-opentelemetry-distro`, `opentelemetry-instrument python -m tower_mcp`).
  Until then the nightly job sees zero calls and reports `checked: 0`.
- Web chat (build-log/20): the agent runtime's JWT authorizer passing `Authorization` through
  (`request_header_allowlist`); whether a JWT caller must send the Runtime session header; whether the function
  URL (`auth_type NONE`) needs `lambda:InvokeFunction` as well as `lambda:InvokeFunctionUrl`.
- Two-way SMS: attach the `…-sms-replies` topic to an origination number in AWS End User Messaging.

## Cost

See `artifacts/cost.md`: the estimate before deployment, plus the procedure for the measured numbers.
`make down` removes everything, except KMS keys, which wait out their 7-day deletion window. ECR repositories
use `force_delete` and Secrets Manager uses a 0-day recovery window, so a re-deploy does not collide.

## EKS (prompt 14)

The EKS portability target is a second root, `deploy/terraform/eks`, with the module `modules/eks`. It reads this
root's state through `terraform_remote_state`. For that, this root has extra outputs: `vpc_id`, `vpc_cidr`,
`public_subnet_ids`, `private_subnet_ids`, `table_arns` and `enable_nat_gateway`.

The second root creates:

- an EKS cluster with one node group of 2 x `t4g.medium` (arm64), on demand, in this VPC's public subnets;
- IRSA roles per service, scoped to this stack's tables, keys, SNS topic and one Bedrock model, with one wildcard:
  SMS to a phone number;
- the AWS Load Balancer Controller.

`make down-eks` destroys only that root. `terraform test` in `modules/eks` asserts the IRSA policies with a mock
provider. See `eks/README.md`.
